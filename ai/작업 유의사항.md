# COMET 작업 유의사항

작업 시작 전에 읽는 파일. **또 밟을 지뢰**만 모은다. 하루치 사건은 `logs/`.

## 모델 호출

### reasoning 모델은 `num_predict` 를 사고와 본문이 나눠 쓴다
- **증상:** 답이 빈 문자열. 느린데(15~50초) 아무 말도 안 함. 컨텍스트가 길수록 더 자주.
- **원인:** gemma4 는 사고를 `message.thinking` 필드로 따로 준다. `num_predict` 는 사고+본문 합계라,
  상한을 사고가 다 먹으면 `content` 가 0자. `<think>` 태그 필터로는 안 잡힌다(태그가 아니라 필드).
- **해법:** `think=False` 를 준다. comet.py 는 `_gen()` 기본값, analyst·vision 은 각자 `_chat()`.
  **새로 `ollama.chat` 을 직접 부르는 곳을 만들면 반드시 `think=False`** (또는 사고 몫까지 상한 4096+).
  확인은 `content` 와 `thinking` 길이를 **둘 다** 찍어볼 것.
- **당한 날:** 2026-09-15 (06-24 안정성 패치의 1024 상한과 만나 COMET 전체가 벙어리였음)

### 진단은 코드 읽기보다 직접 대화시키기가 먼저
- **증상:** 코드만 읽고 원인 후보를 늘어놓다가 주범을 놓침.
- **해법:** `comet.Comet().respond(질문, speak=False)` 로 몇 턴 돌려 **답 길이·시간**부터 본다.
- **주의:** 이렇게 돌리면 `comet_history.json` 에 대화가 쌓인다 → 먼저 백업. 그리고 `Comet()` 생성 시
  저장된 자율모드(brief 등)가 복원돼 스레드가 뜬다.
- **⚠️그 스레드는 진짜로 쏜다.** `autonomy_config.json` 의 `brief.enabled=true` 인데 `last_date` 가
  지난 날짜면, 인스턴스를 만든 지 `check_sec`(기본 600초) 뒤 첫 점검에서 **27b 를 돌리고
  텔레그램을 실제로 전송한다.** 검증하려고 만든 인스턴스가 호윤 폰에 알림을 보낸다.
  → 테스트는 **인스턴스 없이** 해당 메서드만 직접 부르고, `notify` 는 가짜 모듈로 갈아끼운다
  (`sys.modules["notify"] = 가짜`). 2026-09-17 은 이 방식으로 푸시 게이트를 검증했다.
- **당한 날:** 2026-09-15 (2026-09-17 에 전송까지 간다는 걸 확인)

## 도구

### 코드 패치를 Bash heredoc 으로 넣지 말 것
- **증상:** ① 문자열 안 `\\n` 이 실제 줄바꿈으로 들어가 `SyntaxError` ② 따옴표 섞인 긴 heredoc 이
  `unexpected EOF while looking for matching '` 로 통째로 실패(파일 안 바뀜).
- **해법:** 코드 수정은 Edit/Write 도구. 셸은 컴파일·실행·검증에만.
- **당한 날:** 2026-09-15 (두 번)

### 셸이 두 개다 — Bash 와 PowerShell 문법을 섞지 말 것
- **증상 ①** 커밋 메시지 앞뒤에 `@` 가 붙음. PowerShell 히어스트링 `@'…'@` 를 Bash 에 쓴 것
  (bash 는 `@'` 를 '리터럴 @ + 따옴표 시작'으로 읽는다). → Bash 에선 `<<'EOF'` 히어독,
  또는 `git commit -F 파일`.
- **증상 ②** 데몬에 한글을 보내면 **400 Bad Request**. 인증·라우팅 문제가 아니라 셸이 한글을
  UTF-8 로 안 넘겨 본문이 깨진 것(데몬은 `utf-8` 로 decode). `curl -d '{"text":"할일"}'` 이 그대로 실패.
- **해법:** 한글이 섞인 요청·파일은 **파이썬으로** 보낸다(`urllib` + `json.dumps(...).encode("utf-8")`).
  재사용 스크립트: `scratchpad/ask.py` (돌고 있는 데몬에 말 걸기, 토큰 인증 포함).
- **당한 날:** 2026-09-17 (둘 다)

## 이슈 알림 (issues.py)

### 커뮤니티 긁기는 조용히 0건이 된다
- **원인:** 디시·클리앙·긱뉴스는 공식 API 없는 HTML 파싱. 사이트 구조가 바뀌면 에러 없이 빈 목록.
- **해법:** `python issues.py --sources` 로 소스별 건수 확인. 0건이면 파싱부터 의심.
  공감수·추천수가 원래 안 붙는 게시판도 있다(클리앙 새소식 → 조회수로 판정).
- **당한 날:** 2026-09-15

### 강도 기준을 바꾸면 실제 판정 목록을 뽑아서 소음부터 볼 것
- **증상:** 추천수만 보면 밈글이 "볼만함"으로 올라온다(디시 "대통령 티어표.jpg", 레딧 밈).
- **해법:** 분야 단어 필터 + 커뮤니티 단독은 볼만함까지. 점수 없는 소스(레딧 RSS)는 단독 잔잔.
- **당한 날:** 2026-09-15
