# COMET 작업 유의사항

작업 시작 전에 읽는 파일. **또 밟을 지뢰**만 모은다. 하루치 사건은 `logs/`.

## 모델 호출

### reasoning 모델은 `num_predict` 를 사고와 본문이 나눠 쓴다
- **증상:** 답이 빈 문자열. 느린데(15~50초) 아무 말도 안 함. 컨텍스트가 길수록 더 자주.
- **원인:** gemma4 는 사고를 `message.thinking` 필드로 따로 준다. `num_predict` 는 사고+본문 합계라,
  상한을 사고가 다 먹으면 `content` 가 0자. `<think>` 태그 필터로는 안 잡힌다(태그가 아니라 필드).
- **해법:** `think=False` 를 준다. comet.py 는 `_gen()` 기본값, analyst·vision 은 각자 `_chat()`.
  **새로 `ollama.chat` 을 직접 부르는 곳을 만들면 반드시 `think=False`** (또는 사고 몫까지 상한 4096+).
  확인은 `content` 와 `thinking` 길이를 **둘 다** 찍어볼 것.
- **당한 날:** 2026-09-15 (06-24 안정성 패치의 1024 상한과 만나 COMET 전체가 벙어리였음)

### 진단은 코드 읽기보다 직접 대화시키기가 먼저
- **증상:** 코드만 읽고 원인 후보를 늘어놓다가 주범을 놓침.
- **해법:** `comet.Comet().respond(질문, speak=False)` 로 몇 턴 돌려 **답 길이·시간**부터 본다.
- **주의:** 이렇게 돌리면 `comet_history.json` 에 대화가 쌓인다 → 먼저 백업. 그리고 `Comet()` 생성 시
  저장된 자율모드(brief 등)가 복원돼 스레드가 뜬다.
- **⚠️그 스레드는 진짜로 쏜다.** `autonomy_config.json` 의 `brief.enabled=true` 인데 `last_date` 가
  지난 날짜면, 인스턴스를 만든 지 `check_sec`(기본 600초) 뒤 첫 점검에서 **27b 를 돌리고
  텔레그램을 실제로 전송한다.** 검증하려고 만든 인스턴스가 호윤 폰에 알림을 보낸다.
  → 테스트는 **인스턴스 없이** 해당 메서드만 직접 부르고, `notify` 는 가짜 모듈로 갈아끼운다
  (`sys.modules["notify"] = 가짜`). 2026-09-17 은 이 방식으로 푸시 게이트를 검증했다.
- **당한 날:** 2026-09-15 (2026-09-17 에 전송까지 간다는 걸 확인)

## 도구

### 코드 패치를 Bash heredoc 으로 넣지 말 것
- **증상:** ① 문자열 안 `\\n` 이 실제 줄바꿈으로 들어가 `SyntaxError` ② 따옴표 섞인 긴 heredoc 이
  `unexpected EOF while looking for matching '` 로 통째로 실패(파일 안 바뀜).
- **해법:** 코드 수정은 Edit/Write 도구. 셸은 컴파일·실행·검증에만.
  어쩔 수 없이 파이썬으로 치환할 땐 줄바꿈이 든 문자열은 `chr(10)` 으로 쓰고, 끝나면 `ast.parse` 로 확인.
- **곁가지:** ③ `issues.py`·`comet.py`·`voice.py` 는 **CRLF** 다 — 파이썬 치환이 안 맞는다(읽을 때
  `\r\n`→`\n`, 쓸 때 되돌림). `autonomy.py`·`daemon.py` 는 LF. ④ git-bash 의 `/tmp` 는 윈도우 파이썬이 못 찾는다.
- **당한 날:** 2026-09-15 (두 번) · 2026-09-17 (train_ayaka.py) · 2026-09-18 (autonomy 도움말, comet `_start_debate` — 유의사항에 있는데 또)

### 데몬은 재시작하기 전까지 옛 코드로 돈다 — 그리고 끄는 건 호윤이 한다
- **증상:** 고치고 검증까지 했는데 실제 알림·말걸기는 그대로. 데몬(`run_daemon.bat` 창)이 import 해둔 옛 모듈로 돈다.
- **함정:** 호윤이 허락해도 **자동 권한 분류기가 `Stop-Process`/`taskkill` 을 거부**한다("작업 방해"). 우회하지 말 것.
- **해법:** 커밋 → "데몬 창 닫아줘" → 호윤이 닫으면 포트 8765 비었는지 보고 `Start-Process run_daemon.bat`
  → `send_comet.py "알림"` 등으로 새 코드인지 확인(도움말 문구·`talk.log` 의 '귀 준비 완료').
  옛 데몬이 떠 있는 동안 `autonomy_config.json` 을 고쳤으면 **알림 명령을 보내지 말 것** — 옛 코드가 저장하며 덮는다.
- **당한 날:** 2026-09-17~18 (재시작 11번)

### 소리·볼륨을 건드리는 코드는 테스트에서 가짜로 바꿀 것
- `voice.Mouth.speak` 는 스피커로 나가고, `voice.ducker.on()` 은 **호윤 PC 의 실제 앱 볼륨**을 낮춘다.
  흐름 테스트에선 `ducker.on/off` 를 호출 횟수만 세는 가짜로, `issues._say`·`issues.popup` 도 가짜로.
  실물로 돌릴 땐 짧게, 끝나고 볼륨이 돌아왔는지 값을 찍어 확인(돌려놓는 `recover()` 도 있다).
- **당한 날:** 2026-09-18 (덕킹 실측은 일부러 실물로 1초)

### 테스트에서 DB만 임시로 바꾸면 '내보내기'가 실물을 덮는다
- **증상:** 임시 DB 로 잘 격리했다고 믿었는데 `ai/TODO.md` 가 테스트 할일(RawCut 납품본 …)로 덮여 있었다.
- **원인:** `memory_db.DB_PATH` 만 임시로 돌리고 `todo_box.EXPORT` 는 그대로 둬서, 접수·닫기 때마다
  도는 `export()` 가 **진짜 파일**에 썼다. `issue_box.EXPORT` 도 같은 모양이다.
- **해법:** 테스트 첫머리에 **DB 와 내보내기 경로를 둘 다** 갈아끼운다.
  `memory_db.DB_PATH = 임시` + `todo_box.EXPORT = 임시`. 그리고 검증 끝에
  "실물에 테스트 내용이 안 들어갔나"를 한 줄 넣어두면 다음에 또 새면 바로 잡힌다.
- **당한 날:** 2026-09-17 (테스트 6개 중 3개가 새고 있었다)

### 셸이 두 개다 — Bash 와 PowerShell 문법을 섞지 말 것
- **증상 ①** 커밋 메시지 앞뒤에 `@` 가 붙음. PowerShell 히어스트링 `@'…'@` 를 Bash 에 쓴 것
  (bash 는 `@'` 를 '리터럴 @ + 따옴표 시작'으로 읽는다). → Bash 에선 `<<'EOF'` 히어독,
  또는 `git commit -F 파일`.
- **증상 ②** 데몬에 한글을 보내면 **400 Bad Request**. 인증·라우팅 문제가 아니라 셸이 한글을
  UTF-8 로 안 넘겨 본문이 깨진 것(데몬은 `utf-8` 로 decode). `curl -d '{"text":"할일"}'` 이 그대로 실패.
- **해법:** 한글이 섞인 요청·파일은 **파이썬으로** 보낸다(`urllib` + `json.dumps(...).encode("utf-8")`).
  재사용 스크립트: `scratchpad/ask.py` (돌고 있는 데몬에 말 걸기, 토큰 인증 포함).
- **당한 날:** 2026-09-17 (둘 다)

## 이슈 알림 (issues.py)

### 커뮤니티 긁기는 조용히 0건이 된다
- **원인:** 디시·클리앙·긱뉴스는 공식 API 없는 HTML 파싱. 사이트 구조가 바뀌면 에러 없이 빈 목록.
- **해법:** `python issues.py --sources` 로 소스별 건수 확인. 0건이면 파싱부터 의심.
  공감수·추천수가 원래 안 붙는 게시판도 있다(클리앙 새소식 → 조회수로 판정).
- **당한 날:** 2026-09-15

### 강도 기준을 바꾸면 실제 판정 목록을 뽑아서 소음부터 볼 것
- **증상:** 추천수만 보면 밈글이 "볼만함"으로 올라온다(디시 "대통령 티어표.jpg", 레딧 밈).
- **해법:** 분야 단어 필터 + 커뮤니티 단독은 볼만함까지. 점수 없는 소스(레딧 RSS)는 단독 잔잔.
  강도를 '보통'으로 내리면 칼럼·질문형 제목이 울린다 → `OPINION`(issues.py) 으로 굵직 아니면 잔잔.
- **당한 날:** 2026-09-15 · 2026-09-17 ("주식 시장이 … 말하고 있을까" 가 울려 호윤 당황)

### 비인증 공개 API 는 몰아 부르면 IP 째 막힌다 — 탐색도 천천히
- **증상:** 블루스카이 `api.bsky.app` 검색이 몇 분 새 ~15회 만에 `403 Request forbidden by administrative rules`,
  10분 넘게 안 풀림(UA 바꿔도 동일). 레딧 RSS 는 연달아 부르면 즉시 429.
- **해법:** 소스 탐색·검증 때도 요청 수를 세고 간격을 둔다. 코드에는 호출 간격 + 403/429 뒤 긴 휴식
  (`BSKY_GAP`·`BSKY_BACKOFF`)을 넣고, 실패는 '반응 0'이 아니라 '확인 못 함'(`_FAILED` 로그).
  `public.api.bsky.app` 검색은 원래 403, 검색은 `OR` 불가(공백=AND).
- **당한 날:** 2026-09-17

### 이미 알린 것 거르기는 '걸린 것 중 최고 강도'와 비교
- **증상:** 굵직으로 알린 기사가 2분마다 반복. 비슷한 기록 중 처음 걸린 옛 저강도 기록과 비교해 "강도 올랐다"로 착각.
- **남은 약점:** `_similar` 는 세 단어만 겹쳐도 같은 사건 — 다른 사건이 묻힐 수 있다(안 고침).
- **당한 날:** 2026-09-17

## 목소리·듣기 (voice.py · gpt-sovits)

### 아야카(GPT-SoVITS)는 숫자·기호를 못 읽는다
- 한국어 g2p 가 소수점·%·~ 를 제대로 못 읽어 "2.8%" → "이-". `clean_for_speech` 가 `~`·`-` 를 먼저 지운다.
  → `speak_numbers()` 를 **정리보다 먼저**. 숫자는 붙여 읽기(이점팔퍼센트), 소수 끝 0 생략, 단위 앞 고유어.
  새 단위를 `_COUNTERS` 에 넣을 땐 '달러'(달)·'개월'(개)처럼 앞 글자가 겹치는 말을 제외 목록에.
- **당한 날:** 2026-09-18

### 녹음을 의심할 땐 RMS 말고 '걸린 시간 대비 녹음 길이'부터 본다
- **증상:** 받아쓴 문장이 중간중간 빠지거나 뭉개진다. talk.log 의 RMS·초 는 정상으로 보인다.
- **원인:** `sd.rec` 를 짧은 칸마다 새로 열면 칸과 칸 사이가 통째로 빠진다(스트림을 여닫는 시간).
  실측 15초 분량을 받는 데 **22.6초** = 말의 약 1/3 유실. 소리 크기만 보면 멀쩡해 보여서 모델 탓을 하게 된다.
- **해법:** 연속 `sd.InputStream` + 콜백으로 받고 판정만 칸 단위로. 검증은 **경과 시간 ≈ 녹음 길이**
  (`len(audio)/sr`) 한 줄이면 끝난다. 이 한 줄이 없어서 9/17 에 "녹음은 문제 없다"고 잘못 적었다.
- **당한 날:** 2026-09-18 (9/17 에 헛짚고 하루 뒤에 찾음)

### 마이크가 작으면 코드로는 못 고친다 — 진폭부터 재고 호윤에게 넘길 것
- **증상:** 자동 종료·문턱을 아무리 손봐도 받아쓰기가 엉뚱하다(`광고는 예방과 realiz`).
- **원인:** 입력 자체가 작다. 정상은 최대진폭 **0.2~0.5**, 이 PC 의 C300 은 **0.018(MME)·0.007(WASAPI)** 이었다.
  Windows 캡처 볼륨(57%)보다 **마이크 본체 게인 노브**가 주범. 증폭은 잡음도 같이 키운다(코드 상한 20배).
- **해법:** `np.abs(a).max()` 를 먼저 찍는다. 0.05 밑이면 코드 문제가 아니다 — 게인을 올려달라고 하고,
  올린 뒤 다시 잰다. ※WASAPI 장치는 16kHz 로 못 연다(`Invalid sample rate -9997`) — 48kHz 로 열 것.
- **당한 날:** 2026-09-18

### whisper 를 반정밀도로 올리면 LayerNorm 만 float 로 되돌릴 것
- `.half()` 만 하면 `expected scalar type Float but found Half`. LayerNorm 모듈만 `.float()`.
- 음성인식이 이상하면 먼저 `talk.log` 의 `last_stats`(녹음 초·최대 RMS)로 녹음 문제인지 받아쓰기 문제인지 가른다.

### gpt-sovits 빌드(윈도우) — VS 18 을 setuptools 가 못 찾는다

  PowerShell 로 가져와(`cmd /c "vcvars64.bat >nul && set"` 파싱) `DISTUTILS_USE_SDK=1`·`MSSdk=1`.
  .bat 로 하면 한글 경로(개인프젝)가 깨진다. `pkg_resources` 없음 → `setuptools<81`.
  추론 서버는 `text.chinese` 를 무조건 불러서 jieba_fast·pyopenjtalk 도 필요. PYTHONPATH = 루트 + `GPT_SoVITS`.
